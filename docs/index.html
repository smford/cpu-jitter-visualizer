Hardware Micro-Jitter & Thermal Diagnostics Architecture

1. Unprivileged Hardware Profiling

Browsers execute inside secure, unprivileged sandboxes with restricted hardware access. However, by executing pinned, deterministic mathematical execution epochs inside dedicated Web Workers and timing them via high-resolution performance.now(), we can expose the physical underlying CPU behavior and OS kernel scheduling interruptions.

2. Anomaly Signatures

  • OS Kernel Context Switches (>500µs – 5.0ms): Isolated high-amplitude spikes where the OS preemptive scheduler interrupts the Web Worker thread to service hardware interrupts, OS timers, or higher-priority processes.
  • L3 Cache Contention & Core Migration (60µs – 300µs): Jitter induced when CPU cores contend for shared L3 cache lines or when the OS scheduler migrates a thread to another CPU core.
  • Thermal Throttling: Sustained baseline execution degradation across active cores. When high thermal loads cause the CPU to heat up, the thermal governor scales down CPU clock frequencies (P-states), increasing the execution duration for identical instruction batches.

3. Zero-Allocation Shared Memory & Atomics

When Cross-Origin Isolation (COOP/COEP) is active, worker threads stream timing samples directly into a pre-allocated SharedArrayBuffer ring buffer using Atomics.store. This guarantees zero garbage collection interference in the measurement hot loop.

4. GitHub Pages & coi-serviceworker

Static hosts like GitHub Pages do not configure custom response headers by default. This application includes coi-serviceworker.min.js, which dynamically injects Cross-Origin-Opener-Policy: same-origin and Cross-Origin-Embedder-Policy: require-corp. If service workers are disabled or before initial reload, the benchmark automatically falls back to Transferable ArrayBuffers with zero interruption.
